บทสุดท้ายนี้เอาทุกอย่างที่เรียนมาไปใช้ใน**โลกจริง** A/B testing คือการทดลองแบบสุ่ม (RCT จากบท Hypothesis Testing) ที่บริษัทเทคใช้ตัดสินใจแทบทุกเรื่อง ตั้งแต่สีปุ่มไปจนถึงโมเดล recommendation สไลด์บทนี้ (ได้รับความอนุเคราะห์จาก Charin Polpanumas, Data Scientist @ Amazon) เน้น**การออกแบบการทดลอง**มากกว่าการคำนวณ ซึ่งตรงกับข้อสอบปี 2024 ที่ออกเป็น**ข้อเขียน 10 คะแนน**

## ทำไมต้องทดลอง? Correlation ไม่ใช่ Causation

### มีมจากสไลด์: Diet Coke

ทวีตเก่าบอกว่า “ไม่เคยเห็นคนผอมดื่ม Diet Coke เลย” **สิ่งที่สังเกตได้:** คนที่ดื่ม Diet Coke มักอ้วน แต่อธิบายได้สองทาง

- **A:** Diet Coke ทำให้อ้วน
- **B:** คนที่อ้วนอยู่แล้วเลือกดื่ม Diet Coke (เพราะอยากลดน้ำหนัก)

**ถ้ามีแค่ข้อมูลจากการสังเกต (observational data) เราบอกไม่ได้เลยว่าแบบไหนถูก** ข้อมูลบอกได้แค่ว่าสองอย่าง “ไปด้วยกัน” แต่ไม่บอกว่าอะไรเป็นเหตุ

### Simpson's paradox

<Example title="ตัวอย่างจากสไลด์: ยาดีหรือยาแย่?">

| | ควบคุม: หัวใจวาย | ควบคุม: ไม่วาย | ได้ยา: หัวใจวาย | ได้ยา: ไม่วาย |
|---|---|---|---|---|
| **ผู้หญิง** | 1 | 19 | 3 | 37 |
| **ผู้ชาย** | 12 | 28 | 8 | 12 |
| **รวม** | 13 | 47 | 11 | 49 |

<Solution>

- **ผู้หญิง:** กลุ่มควบคุมหัวใจวาย 1/20 = **5%** แต่กลุ่มได้ยา 3/40 = **7.5%** → ยาแย่สำหรับผู้หญิง
- **ผู้ชาย:** กลุ่มควบคุม 12/40 = **30%** แต่กลุ่มได้ยา 8/20 = **40%** → ยาแย่สำหรับผู้ชาย
- **รวมทุกคน:** กลุ่มควบคุม 13/60 ≈ **22%** แต่กลุ่มได้ยา 11/60 ≈ **18%** → ยา “ดี” สำหรับคนทั่วไป?!

ยาแย่กับทั้งผู้หญิงและผู้ชาย แต่พอรวมกลับดูดี เพราะ**ผู้หญิงมีความเสี่ยงหัวใจวายต่ำอยู่แล้ว และผู้หญิงส่วนใหญ่อยู่ในกลุ่มได้ยา** (40 จาก 60 คน) ส่วนผู้ชายที่เสี่ยงสูงไปกระจุกอยู่ในกลุ่มควบคุม เพศจึงส่งผลทั้งต่อ “ได้ยาหรือไม่” และ “หัวใจวายหรือไม่”

</Solution>
</Example>

<Def title="Confounder (ตัวแปรกวน)">

ตัวแปรที่ส่งผล**ทั้งต่อตัวแปรต้น (independent variable) และตัวแปรตาม (dependent variable)** เช่น เพศในตัวอย่างนี้ ส่งผลทั้งต่อการได้ยาและต่อการเกิดหัวใจวาย

$$
\text{Drug} \leftarrow \text{Gender} \rightarrow \text{Heart attack}
$$

ถ้าไม่คุม confounder ความสัมพันธ์ที่เห็นอาจกลับทิศได้ **การสุ่ม (randomization)** ใน A/B test ตัดลูกศรจาก confounder ไปหาตัวแปรต้นทิ้ง เพราะเหรียญที่ใช้สุ่มไม่สนใจเพศของใคร

</Def>

<Example title="โจทย์ Q42 ในสไลด์ (คนตอบถูกแค่ 1%)">

ธนาคารแห่งประเทศไทยออกมาตรการอายัดบัญชีม้า (scam) โดยรู้ว่า

- ที่ยอดเงินเท่ากัน บัญชีม้ามีโอกาสถูกอายัดมากกว่าบัญชีปกติ
- ในบัญชีม้าด้วยกัน บัญชียอดสูงมีโอกาสถูกอายัดมากกว่ายอดต่ำ
- ในบัญชีปกติด้วยกัน บัญชียอดสูงก็มีโอกาสถูกอายัดมากกว่ายอดต่ำ

ข้อสรุปไหน**ต้อง**จริง? (i) โดยรวมแล้ว บัญชีม้ามีโอกาสถูกอายัดมากกว่าบัญชีปกติ (ii) โดยรวมแล้ว บัญชียอดสูงมีโอกาสถูกอายัดมากกว่ายอดต่ำ — ตัวเลือก 1) (i) อย่างเดียว 2) (ii) อย่างเดียว 3) ทั้งคู่ 4) ไม่มีข้อไหนต้องจริง

<Solution>

**ตอบ 4) ไม่มีข้อไหนต้องจริง** เพราะ Simpson's paradox: ข้อมูลทั้งหมดที่ให้มาเป็นแบบ “แยกกลุ่ม” พอรวมกลุ่ม ผลขึ้นกับว่าแต่ละกลุ่มมีสัดส่วนเท่าไร (ตัวเลขต่อไปนี้ผมสมมติเองเพื่อแสดงว่าทำได้จริง)

- **(i) ไม่จำเป็นต้องจริง:** ให้โอกาสถูกอายัดเป็น ม้ายอดต่ำ 0.2, ปกติยอดต่ำ 0.1, ม้ายอดสูง 0.9, ปกติยอดสูง 0.8 (ตรงเงื่อนไขทุกข้อ) ถ้าบัญชีม้าเกือบทั้งหมดยอดต่ำ และบัญชีปกติเกือบทั้งหมดยอดสูง โดยรวมม้าจะโดนอายัดประมาณ 0.2 แต่บัญชีปกติประมาณ 0.8
- **(ii) ไม่จำเป็นต้องจริง:** ให้ ม้ายอดต่ำ 0.85, ม้ายอดสูง 0.95, ปกติยอดต่ำ 0.05, ปกติยอดสูง 0.1 ถ้าบัญชียอดต่ำเกือบทั้งหมดเป็นม้า และยอดสูงเกือบทั้งหมดเป็นบัญชีปกติ โดยรวมยอดต่ำจะโดนอายัดประมาณ 0.85 แต่ยอดสูงแค่ประมาณ 0.1

</Solution>
</Example>

### 6 ขั้นของ A/B test in the Wild

<Tip title="Step-by-step guide (โครงคำตอบข้อเขียน)">

1. **Define relevant metrics** เลือก metric ที่ใช่
2. **Split samples into comparable groups** แบ่งกลุ่มให้เทียบกันได้
3. **Choose statistical tests and validate their assumptions** เลือก test และตรวจ assumption
4. **Decide on stopping criteria** ตัดสินใจว่าจะหยุดเมื่อไร
5. **Run and monitor the experiment** รันและเฝ้าดู
6. **Analyze results and suggest actions** วิเคราะห์และเสนอสิ่งที่ควรทำ

</Tip>

### Granularity: หารด้วยอะไร?

metric ที่ใช้บ่อยที่สุดใน A/B test คือ**ความน่าจะเป็นของเหตุการณ์** = จำนวนเหตุการณ์ / จำนวนหน่วย คำถามคือ “หน่วย” คืออะไร

| ตัวหาร (denominator) | ความหมาย |
|---|---|
| **Hits / Impressions** | จำนวนครั้งที่เปิดหน้า |
| **Sessions** | จำนวนครั้งที่เข้าเว็บ (หมดอายุหลังไม่ใช้งาน 15–30 นาที) |
| **Cookies** | จำนวน cookie ที่เข้าเว็บ/หน้านั้น |
| **User IDs / Reach** | จำนวนผู้ใช้ที่ล็อกอิน |
| **Device IDs** | จำนวนอุปกรณ์ |
| **People** | จำนวนคนจริงๆ |

| metric | ข้อสังเกต |
|---|---|
| # checkout / # hits | นับซ้ำเมื่อรีเฟรชหน้า |
| # checkout / # sessions | นับซ้ำเมื่อเข้ามาแล้วไม่ทำอะไร แต่ดีสำหรับดูว่าสินค้าไหนขายได้ในไม่กี่ครั้งที่เข้า |
| # checkout / # cookies บนหน้าสินค้า | ใช้ “ผู้ใช้” เป็นตัวหาร รวมทั้งคนล็อกอินและไม่ล็อกอิน แต่คนเดียวใช้หลายเบราว์เซอร์/อุปกรณ์จะนับซ้ำ |
| # payment / # cookies บนหน้าสินค้า | จับการซื้อที่**จ่ายเงินสำเร็จ**จริง |
| # payment / # user IDs | คนที่ไม่ล็อกอินทั้งหมดถูกนับเป็น user ID เดียว |
| # payment / # people | “คน” คือใคร? วัดยากมาก |

ตัวอย่างใน hamzada: ระบบแนะนำสินค้าชิ้นต่อไป → วัด**การซื้อภายใน session** · แจ้งสิทธิประโยชน์สมาชิก → วัด **retention เดือนถัดไป** · แนะนำสินค้าวันพ่อปีหน้า → วัด**การซื้อในเดือนถัดไป**

</Tip>

### Attribution period: นับการเดินทางของลูกค้ายาวแค่ไหน

<Example title="ตัวอย่างจากสไลด์">

ลูกค้าคนหนึ่ง (cookie เดียว) เข้าเว็บวันที่ 1, วันที่ 4 และซื้อวันที่ 6 ใช้ metric = # payment / # cookies ต่อช่วง X วัน

- **One-day attribution:** นับเป็น 3 journeys สำเร็จ 1 → 1/3
- **Three-day attribution:** นับเป็น 2 journeys สำเร็จ 1 → 1/2
- **One-week attribution:** นับเป็น 1 journey สำเร็จ 1 → 1/1

</Example>

ช่วงที่เหมาะขึ้นกับว่า**การเดินทางหนึ่งครั้งของลูกค้ายาวเท่าไร** วิธีรู้คือ **plot ออกมาดู** (สไลด์แสดงว่าคนส่วนใหญ่ซื้อจบภายในวันแรก) เว็บ e-commerce อย่าง Amazon ส่วนใหญ่จบในวันเดียว แต่การจองตั๋วเครื่องบิน (Air Asia) หรือสมัครงาน (LinkedIn) อาจใช้เป็นสัปดาห์หรือเดือน

<Def title="Event-based vs Cohort-based">

- **Event-based** (conversion rate ของเดือนสิงหาคม) = conversion ที่**เกิดในเดือนสิงหาคม** ÷ จำนวนผู้ใช้ที่เข้ามาในเดือนสิงหาคม
- **Cohort-based** (conversion rate ของ cohort สิงหาคม) = conversion **ภายใน X วัน**ของคนที่เข้ามาในสิงหาคม ÷ จำนวนผู้ใช้ที่เข้ามาในเดือนสิงหาคม

ต่างกันตรงที่ cohort-based ติดตาม “คนกลุ่มเดิม” ต่อไปอีก X วันแม้จะข้ามเดือน ส่วน event-based นับแค่เหตุการณ์ที่เกิดในเดือนนั้น (การบ้าน 12 ข้อ 3 ให้คำนวณทั้งสองแบบ)

</Def>

เรื่องเดียวกันเกิดกับ **ads attribution**: ลูกค้าเห็นโฆษณาบน FB มือถือ, ค้น Google, เข้าเว็บตรง, เห็น FB บนคอม แล้วค่อยซื้อ ยอดขายควรยกเครดิตให้ช่องทางไหน?

### Assumed distributions

Hypothesis testing แบบ frequentist ต้อง**รู้ variance ของข้อมูล** จึงต้องสมมติการแจกแจงให้ถูกกับชนิดข้อมูล

| ชนิดข้อมูล | การแจกแจงที่มักสมมติ |
|---|---|
| ความน่าจะเป็นของเหตุการณ์ (ซื้อ/ไม่ซื้อ) | **Bernoulli** → variance $p(1-p)$ |
| รายได้เฉลี่ยต่อผู้ใช้, ตำแหน่งที่คลิกเฉลี่ย | **Exponential** |
| ส่วนสูง, น้ำหนัก, คะแนนสอบ, ความคลาดเคลื่อนการวัด | **Normal / Student t** |

และข้อมูลต้อง **i.i.d.** ด้วย **จะแน่ใจได้ยังไง? Plot ออกมาดู!** สไลด์แสดงกราฟ “ตำแหน่งที่คลิกในหน้ารายการสินค้า” ที่พุ่งสูงตรงตำแหน่งแรกแล้วลดลงเรื่อยๆ ไม่ใช่ normal แน่นอน

### Robustness vs Sensitivity

เวลาต้องเลือก summary statistic มาทดสอบ (ตัวอย่างในสไลด์: latency ของวิดีโอ YouTube ที่เลือกได้ว่าจะใช้ median หรือ percentile ที่ 80, 85, 90, 99)

- **Robust:** ถ้าของเหมือนกัน ค่าสถิติต้อง**ไม่เปลี่ยน** (วิดีโอ latency เท่ากัน ค่าที่ได้ควรนิ่ง)
- **Sensitive:** ถ้าของต่างกัน ค่าสถิติต้อง**เปลี่ยนตาม** (วิดีโอ latency ไล่ระดับ ค่าที่ได้ควรไล่ตาม)

percentile สูงมากๆ (เช่น 99th) มัก sensitive แต่ไม่ robust ส่วน median มัก robust แต่อาจไม่ sensitive พอ

<Tip title="Design journal ขั้นที่ 1">

**Metric** = # payment / # cookie-days แต่ละ cookie เป็น **Bernoulli trial** (metric จึงเป็น normalized binomial)

</Tip>

hypothesis test ต้องการข้อมูล **i.i.d.** การเลือก “หน่วยที่ใช้สุ่มแบ่งกลุ่ม” จึงสำคัญ

### Control for X: คุม confounder

Simpson's paradox เกิดใน A/B test ได้เหมือนกัน ในตัวอย่าง hamzada **ช่องทางที่ผู้ใช้เข้ามาถึงหน้าสินค้า** เป็น confounder ได้

- คนที่มาจาก**หน้าค้นหา** อาจซื้อง่ายกว่า เพราะตั้งใจหาเมล็ดทานตะวันอยู่แล้ว
- คนที่**เข้าเว็บตรง** อาจซื้อน้อยกว่า เพราะน่าจะมาจากโฆษณา

**ทางแก้:** เก็บข้อมูลว่าแต่ละคนมาจากช่องทางไหน แล้ว**ทำ A/B test แยกภายในแต่ละช่องทาง**

### Frame the experiment fairly

สิ่งที่เปลี่ยนอาจส่งผลต่อพฤติกรรมแบบที่ไม่ได้ตั้งใจ เช่น กลุ่มควบคุมมีช่องคอมเมนต์อยู่ด้านล่าง กลุ่มทดลองย้ายไปด้านบน ผู้ใช้อาจ**หาช่องคอมเมนต์ไม่เจอ**ใน UI ใหม่ จำนวนคอมเมนต์ที่ลดลงจึงไม่ได้แปลว่าดีไซน์แย่ อาจต้องบอกผู้ใช้ก่อน

### Multiple experiments

ถ้ารันหลายการทดลองพร้อมกัน (สีซอง แดง/เทา × ราคา ต่ำ/กลาง/สูง × ฟอนต์ชื่อสินค้า หนา/เอียง/ขีดเส้นใต้/ปกติ) **ต้องสุ่มแต่ละการทดลองแยกกันอย่างอิสระ** ถ้าซองแดงบังเอิญได้ราคาต่ำมากกว่า มันอาจขายดีกว่าเพราะ**ถูกกว่า** ไม่ใช่เพราะเป็นสีแดง ยิ่งแบ่งย่อยมาก ยิ่งต้องแน่ใจว่าสุ่มจริง

## ขั้นที่ 3: เลือก test และตรวจ assumption

### สิ่งที่ hypothesis test บอก

<Def title="ประโยคเดียวที่สรุป frequentist test">

**สมมติว่าสิ่งที่เราเชื่ออยู่เป็นจริง** ($H_0$: conversion ไม่ต่างกัน) **โอกาส (p-value)** ที่จะเห็นค่าเฉลี่ยตัวอย่างที่สุดโต่งกว่า**สิ่งที่เห็นอยู่ตอนนี้ (ค่า z ของเรา)** นั้น **น้อยกว่าอัตรา false positive ที่เรายอมรับได้** (significance level: 1%, 5%, 10%)

</Def>

สไลด์แสดง rejection region สามแบบ: หางซ้าย, สองหาง, หางขวา (ขึ้นกับว่าทดสอบ “ดีกว่า”, “ต่าง”, หรือ “แย่กว่า”) การทดสอบแบบ “มากกว่า/น้อยกว่า” (หางเดียว) มี threshold ของ z ที่**สุดโต่งน้อยกว่า** เพราะดูแค่หางเดียว (1.645 เทียบกับ 1.96 ที่ α = 0.05)

### สิ่งที่ hypothesis test **ไม่ได้**บอก (misuse of p-values)

<Warn title="5 ความเข้าใจผิดเรื่อง p-value">

1. p-value **ไม่ใช่**ความน่าจะเป็นที่ $H_0$ จริง หรือที่ $H_A$ ผิด
2. p-value **ไม่ใช่**ความน่าจะเป็นที่ผลที่เห็นเกิดจากความบังเอิญล้วนๆ
3. significance level 0.05 **เป็นแค่ธรรมเนียม** ไม่ใช่กฎธรรมชาติ
4. p-value **ไม่ได้บอกขนาดหรือความสำคัญ**ของผล
5. p-value **ไม่ใช่อัตรา false positive ที่เกิดจริง** ซึ่งขึ้นกับ prevalence (base rate) ของข้อมูล

</Warn>

### Test ที่ใช้กับ conversion rate

metric แบบ Bernoulli ใช้ **two-proportion z-test** จากบท Hypothesis Testing ได้เลย

$$
z = \frac{\hat p_B - \hat p_A}{\sqrt{\hat p(1-\hat p)\left(\dfrac{1}{n_A} + \dfrac{1}{n_B}\right)}}, \qquad \hat p = \frac{x_A + x_B}{n_A + n_B}
$$

ส่วน metric แบบค่าต่อเนื่อง (เช่น รายได้ต่อผู้ใช้) ใช้ t-test (ถ้า variance ไม่เท่ากันใช้ Welch's t-test) และต้องเช็ก assumption ตามบทก่อน

<Tip title="Design journal ขั้นที่ 3">

ใช้ **one-tailed Z test ที่ significance level 5%**

</Tip>

## ขั้นที่ 4: ตัดสินใจว่าจะหยุดเมื่อไร

<Warn title="รันนานพอ อะไรก็ significant">

สไลด์แสดงกราฟค่า z ที่คำนวณจากข้อมูลสะสมของแคมเปญ 60 วัน ค่า z ค่อยๆ ไหลลงจนข้ามเส้น “B ดีกว่า A” ได้ในที่สุด ถ้าไม่กำหนดจุดหยุดไว้ก่อน เราจะหยุดตอนที่ผลถูกใจเสมอ ต้องตั้ง**stopping criteria ก่อนเริ่ม**

</Warn>

### Minimum Detectable Effect (MDE)

<Def title="MDE">

**ความต่างที่เล็กที่สุดที่เราสนใจจะตรวจให้เจอ** (เช่น conversion เพิ่ม 1 เปอร์เซ็นต์พอยต์) เป็นการตัดสินใจทางธุรกิจ: ความต่างเล็กกว่านี้ไม่คุ้มที่จะเปลี่ยน

มีสามอย่างที่ผูกกันอยู่: **effect size d** (ความต่างที่อยากตรวจ), **power** $1 - \beta$ (true positive) และ **significance level α** (false positive)

</Def>

สไลด์แสดงกราฟ power เทียบกับขนาดตัวอย่างต่อกลุ่ม ที่ α = 0.05: ถ้า d = 0.2 ตัวอย่าง 200 ต่อกลุ่มยังได้ power ไม่ถึง 0.8 แต่ถ้า d = 0.8 ใช้แค่ไม่กี่สิบต่อกลุ่ม **ผลยิ่งเล็ก ยิ่งต้องเก็บตัวอย่างมาก**

ดูโครงสร้างของ test statistic อีกครั้ง

$$
\bar Z_j = \frac{\bar X_j - \mu}{\sigma/\sqrt n}
$$

- **σ ใหญ่** (ข้อมูลแกว่งมาก) → ความต่าง (หรือการไม่ต่าง) ตรวจเจอ**ยาก**
- **n ใหญ่** → ความต่าง (หรือการไม่ต่าง) ตรวจเจอ**ง่าย**

### คำนวณขนาดตัวอย่างย้อนกลับ

<Def title="สูตรขนาดตัวอย่างจากสไลด์">

ให้ α = false positive rate (confidence level = 1 − α), β = false negative rate (power = 1 − β)

$$
z_\alpha = \Phi^{-1}(1-\alpha), \qquad z_\beta = \Phi^{-1}(1-\beta)
$$

กลุ่มควบคุมมี n ตัว กลุ่มทดลองมี mn ตัว (**m = split rate**: m = 1 คือ 50/50, m = 2 คือ 33/67) ใช้ pooled variance $\sigma^2$ เท่ากันทั้งสองกลุ่ม

**แนวคิด:** critical value ต้องอยู่ตรงจุดที่ (1) ห่างจาก 0 เป็น $z_\alpha$ เท่าของ SE (คุม α) และ (2) ห่างจาก MDE เป็น $z_\beta$ เท่าของ SE (คุม power)

$$
0 + z_\alpha\sqrt{\sigma^2\left(\frac1n + \frac{1}{mn}\right)} = \text{MDE} - z_\beta\sqrt{\sigma^2\left(\frac1n + \frac{1}{mn}\right)}
$$

$$
z_\alpha + z_\beta = \frac{\text{MDE}}{\sqrt{\sigma^2\left(\frac1n + \frac{1}{mn}\right)}} \quad\Longrightarrow\quad \frac{(m+1)\sigma^2}{mn} = \left(\frac{\text{MDE}}{z_\alpha + z_\beta}\right)^2
$$

$$
n = \frac{m+1}{m}\left(\frac{(z_\alpha + z_\beta)\,\sigma}{\text{MDE}}\right)^2 \qquad\xrightarrow{\;m\,=\,1\;}\qquad n = 2\left(\frac{(z_\alpha + z_\beta)\,\sigma}{\text{MDE}}\right)^2
$$

ถ้าตั้ง power = 50% จะได้ $z_\beta = 0$

</Def>

<Warn title="σ² ของ conversion rate">

metric เป็น Bernoulli ดังนั้น $\sigma^2 = p(1-p)$ ของข้อมูล**ต่อหนึ่งคน** (ใช้ conversion rate เดิมของกลุ่มควบคุมเป็น p) ระวังหน่วยของ MDE ให้ตรงกับ p: ถ้า p = 0.10 แล้ว MDE “1%” แบบ absolute คือ 0.01 (จาก 10% เป็น 11%) ไม่ใช่ 10% × 1% และถ้าทดสอบสองทาง ให้ใช้ $z_{\alpha/2}$ แทน $z_\alpha$

</Warn>

<Example title="ตัวอย่าง: ตัวเลข 11,128 ในสไลด์มาจากไหน">

กราฟในสไลด์เขียนว่า “Minimum required samples at MDE 0.01 = 11128” โดยไม่ได้บอกค่าอื่น ลองตรวจว่าตรงกับ conversion เดิม 10%, one-sided α = 0.05, power 80%, แบ่ง 50/50 ไหม

<Solution label="วิธีทำ (ค่าที่สไลด์ไม่ได้บอก ผมสมมติแล้วคำนวณตรวจ)">

- $\sigma^2 = 0.1 \times 0.9 = 0.09$
- $z_\alpha = z_{0.05} = 1.645$, $z_\beta = \Phi^{-1}(0.8) = 0.842$ → $(z_\alpha + z_\beta)^2 = 2.487^2 = 6.183$
- $n = 2 \times \dfrac{6.183 \times 0.09}{0.01^2} = 11{,}128.6$

ตรงกับสไลด์พอดี (สไลด์ปัดลง ถ้าใช้จริงควรปัดขึ้นเป็น 11,129 คนต่อกลุ่ม)

</Solution>
</Example>

<Example title="ตัวอย่าง: 50/50 vs 80/20">

conversion เดิม 10%, อยากตรวจให้เจอถ้าเพิ่มเป็น 12% (MDE = 0.02), one-sided α = 0.05, power 80% ต้องใช้ตัวอย่างเท่าไรถ้าแบ่ง (ก) 50/50 (ข) 80/20 (กลุ่มควบคุม 80%)?

<Solution>

$\sigma^2 = 0.09$, $(z_\alpha + z_\beta)^2 = 6.183$ และ $\left(\frac{(z_\alpha + z_\beta)\sigma}{\text{MDE}}\right)^2 = \frac{6.183 \times 0.09}{0.0004} = 1391.1$

**(ก) 50/50 (m = 1):** $n = 2 \times 1391.1 = 2782.2$ → กลุ่มละ **2,783** คน รวม 5,566 คน

**(ข) 80/20:** กลุ่มทดลองเป็น 1/4 ของกลุ่มควบคุม → m = 0.25

$$
n = \frac{1.25}{0.25} \times 1391.1 = 5 \times 1391.1 = 6955.4
$$

กลุ่มควบคุม **6,956** คน กลุ่มทดลอง $0.25 \times 6955.4 \approx$ **1,739** คน รวม 8,695 คน

ตรงกับสไลด์ “80/20 ใช้เวลานานกว่า แต่เสี่ยงน้อยกว่า”: ต้องเก็บรวมมากขึ้นประมาณ 56% แต่มีคนเห็นแบบใหม่แค่ 1,739 คน

</Solution>
</Example>

### A/A test

<Def title="A/A test">

- **ตั้งใจ**แบ่ง cookie เป็นกลุ่มควบคุมกับกลุ่มควบคุม (ทั้งสองกลุ่มเห็นแบบเดิม)
- plot การแจกแจงของความต่างของ conversion rate ระหว่างสองกลุ่ม
- จะเห็นว่าความต่างที่เกิดจาก**ความสุ่มล้วนๆ** ใหญ่แค่ไหน (ในสไลด์ส่วนใหญ่อยู่ในช่วงประมาณ ±0.002)
- ใช้ประมาณ pooled sample variance แบบ empirical ได้ (คอร์ส A/B Testing ของ Google บน Udacity อธิบายละเอียด) และช่วยตั้ง MDE: ความต่างที่เล็กกว่าระดับ noise ของ A/A ไม่มีประโยชน์จะไล่ตรวจ

</Def>

## ขั้นที่ 5: รันและเฝ้าดูการทดลอง

### Do not peek!

<Def title="ทำไมห้ามแอบดู">

ถ้า $H_0$ จริง frequentist test **สัญญา**ว่าจะคุม false positive rate ไม่ให้เกิน significance level แต่สัญญานี้ใช้กับการดูผล**ครั้งเดียว**ตอนได้ตัวอย่างครบ **การแอบดูหลายครั้งก่อนกำหนด (แล้วหยุดทันทีที่ significant) ทำลายสัญญานี้** เพราะมันคือการทดสอบหลายครั้ง (multiple testing) แบบแอบๆ

</Def>

สไลด์จำลองการทดลองกลุ่มละ 1,000 ครั้ง:

| | แอบดูไปเรื่อยๆ | ดูครั้งเดียวตอนจบ |
|---|---|---|
| **มีความต่างจริง** ปฏิเสธ $H_0$ | 99.6% | 99.6% |
| **ไม่มีความต่าง** ปฏิเสธ $H_0$ (= false positive) | **22.4%** | 6.4% |

การแอบดูไม่ได้ช่วยให้เจอผลจริงมากขึ้นเลย แต่ทำให้ false positive เพิ่มขึ้นหลายเท่า (สไลด์ใช้มีม “STOP THE COUNT / KEEP COUNTING” ล้อการเลือกหยุดนับตอนที่ผลถูกใจ)

- **กลุ่มถูกแบ่งตามที่ตั้งใจไหม?** ถ้าแบ่งตาม cookie แต่ cookie เดียวเห็นทั้งสองแบบ = หายนะ
- **ตัวแปรที่ต้องคุม ถูกคุมจริงไหม?**
- **Twyman's law:** สถิติไหนที่ดูน่าสนใจเกินไป **เกือบแน่นอนว่าผิด** ให้ตรวจกลไกการแบ่งกลุ่มก่อน ตัวอย่างปัญหาที่เจอบ่อย: developer ใช้ `random()` สุ่มทุกครั้งที่โหลดหน้า แทนที่จะแบ่งตาม cookie, variation หนึ่งโหลดไม่ขึ้น, tracking ไม่ทำงาน
- **ระบบ tracking:** เว็บมักใช้ Google Tag Manager รวบรวม tracking script แล้วส่งไป dashboard วิเคราะห์และแพลตฟอร์มโฆษณา ส่วนแอปมักใช้ Firebase SDK ถ้า tracking พัง ข้อมูลทั้งการทดลองก็ใช้ไม่ได้

### Post-test monitoring

ผลที่ได้**คงอยู่จริง หรือแค่ไฟไหม้ฟาง?** ลูกค้าอาจสนใจแบบใหม่เพราะ**ความแปลกใหม่ (novelty)** แล้วค่อยๆ กลับไปเหมือนกลุ่มควบคุม **ทางแก้:** หลังประกาศผู้ชนะ ให้เหลือกลุ่มควบคุมไว้ส่วนเล็กๆ เพื่อตรวจสอบต่อ

<Tip title="Design journal ขั้นที่ 5">

ตรวจว่าแต่ละ cookie เห็นแค่ variation ที่ถูกกำหนด และ**เหลือ 10% เป็นกลุ่มควบคุม**หลังจบการทดลอง

</Tip>

## ขั้นที่ 6: วิเคราะห์ผลและตัดสินใจ

### Multiple test corrections

**ถ้าทดสอบบ่อยพอ ยังไงก็เจอผล significant** สไลด์: ถ้าทดสอบ**ทุกวัน**ด้วยข้อมูลรายวัน 60 วัน จะมีประมาณ 3 วันที่ปฏิเสธ $H_0$ (60 × 0.05 = 3) แม้ทั้งสองกลุ่มจะมี conversion rate จริงเท่ากัน

<Def title="Bonferroni และ Šidák">

- **Bonferroni:** หาร α ด้วยจำนวน test $\alpha_{\text{new}} = \alpha/m$ (conservative มาก)
- **Šidák:** สมมติว่า test อิสระกัน โอกาสที่**ไม่มี** test ไหน significant เลยเมื่อ $H_0$ จริงทั้งหมดคือ $(1 - \alpha_{\text{Šidák}})^m$ ดังนั้น

$$
\alpha_{\text{overall}} = 1 - (1 - \alpha_{\text{Šidák}})^m \quad\Longrightarrow\quad \alpha_{\text{Šidák}} = 1 - (1 - \alpha_{\text{overall}})^{1/m}
$$

นอกจากนี้ยังมีวิธีที่ซับซ้อนกว่าและ conservative น้อยกว่า เช่น Benjamini-Hochberg (บท Hypothesis Testing)

</Def>

<Example title="ตัวอย่างจากสไลด์: α overall = 0.05, ทดสอบ 10 ครั้ง">

<Solution>

- **Bonferroni:** $0.05/10 = 0.005$
- **Šidák:** $1 - (1 - 0.05)^{1/10} = 1 - 0.95^{0.1} = 0.005116$

ใกล้กันมาก Šidák ใหญ่กว่านิดเดียว (ในสไลด์สูตรตรงตัวอย่างเขียนเลขชี้กำลังเป็น 10 แต่ค่า 0.005116 มาจากเลขชี้กำลัง 1/10 ตามสูตรด้านบน)

</Solution>
</Example>

### ตัดสินใจและเข้าใจความเสี่ยง

เราทำ A/B test เพื่อ**ตัดสินใจทางธุรกิจ** ไม่ใช่เพราะเป็นเครื่องคิดเลข ผลที่ significant แต่ต่างกันนิดเดียวอาจไม่คุ้มค่าเปลี่ยน ส่วนผลที่ไม่ significant ไม่ได้แปลว่าสองแบบเหมือนกัน (ดู “อ่าน p-value ให้ถูก” ในบท Hypothesis Testing)

<Tip title="Design journal ฉบับสมบูรณ์: ซองเมล็ดทานตะวัน">

1. **Metric:** # payment / # cookie-days แต่ละ cookie เป็น Bernoulli trial
2. **Split:** 50/50 ตาม cookie รัน test แยกสำหรับ cookie ที่เข้าเว็บตรง
3. **Test:** one-tailed Z test ที่ significance level 5%
4. **Stopping:** MDE 1% จาก A/A test รันจนได้ X ตัวอย่างต่อ variation (คำนวณจากสูตร) และอย่างน้อยหนึ่งสัปดาห์
5. **Monitor:** ตรวจว่า cookie เห็นแค่ variation ของตัวเอง เหลือ 10% เป็นกลุ่มควบคุมหลังจบ
6. **Analyze:** ทดสอบครั้งเดียวตอนจบ แล้วใช้ซองสีที่ชนะ

</Tip>

## ข้อจำกัด: เมื่อไรไม่ควรทำ A/B test

<Warn title="5 สถานการณ์ที่ A/B test ใช้ไม่ได้ (หรือไม่เหมาะ)">

1. **สิ่งที่สรุปเป็น metric ไม่กี่ตัวไม่ได้** เช่น “ผู้ใช้มีความสุขไหม?”
2. **ของใหม่ทั้งหมด** ไม่ใช่การเทียบแบบ apple-to-apple → ใช้ survey, focus group, design thinking แทน
3. **ผลเกิดช้า** เช่น การเปลี่ยนแปลงทำให้ลูกค้ากลับมาซื้อซ้ำไหม ถ้ารอบซื้อซ้ำคือ 3 เดือน
4. **เหตุการณ์ครั้งเดียว** เช่น เซลใหญ่ 11.11 หรือ Black Friday ไม่มีสองครั้งไหนเหมือนกัน
5. **แบ่งกลุ่มแบบอิสระไม่ได้** เช่น การจัดผังร้านค้าออฟไลน์ของร้านเดียวกัน

</Warn>

<Tip title="บทเรียนจาก A/B testing in the wild">

- **เข้าใจธุรกิจของตัวเอง** เราทำ A/B test เพื่อตัดสินใจในโลกจริง ไม่ใช่เพราะเป็นเครื่องคิดเลข
- **Tracking, tracking, tracking**
- **ทำครบกระบวนการสักครั้ง** สำคัญกว่าพยายามทำทุกขั้นให้สมบูรณ์แบบ
- **เขียน assumption ให้ชัด** และเตรียมรับความเสี่ยง
- **กลุ่มควบคุมจะชนะบ่อยมาก** สิ่งสำคัญคือเราตอบสนองกับผลนั้นยังไง

</Tip>

## ตัวอย่างข้อสอบ: ออกแบบ A/B test (ข้อเขียน)

<Tip title="โครงตอบข้อเขียน A/B test (ใช้ 6 ขั้น)">

1. **Metric:** เลือก relevant metric (ไม่ใช่ vanity) บอกตัวหาร (granularity) และ attribution period พร้อมเหตุผล
2. **Split:** สุ่มตามหน่วยไหน แบ่งกี่ % คุม confounder อะไร ระวังกลุ่มมีปฏิสัมพันธ์กัน
3. **การแจกแจงและ test:** metric แจกแจงแบบไหน (Bernoulli → two-proportion z) one/two-sided α เท่าไร
4. **Stopping:** MDE, power, α → ขนาดตัวอย่าง + รันครบรอบ seasonality
5. **Monitor:** ห้าม peek, sanity check, novelty effect
6. **สรุป:** **เขียน assumption ทุกข้อให้ชัด** (ข้อสอบให้คะแนนตรงนี้)

</Tip>

<Example title="ข้อสอบปี 2024 ข้อ 6: Boss Hamtaro (10 คะแนน)">

Hamtaro ขายคอร์สออนไลน์ราคา 99 บาท ผู้ชมประมาณ **1%** จะกลายเป็น downline ซึ่งทำกำไรรวมเฉลี่ย **10,000 บาท** ต่อคน อีก 99% ให้กำไรแค่ **10 บาท** (ค่าคอร์ส) Koushi-kun เสนอให้เพิ่มวิดีโอในคอร์ส ซึ่งเพิ่มค่า bandwidth จนกำไรจากคนที่ไม่เป็น downline เหลือ **5 บาท** แต่อ้างว่าจะทำให้คนเป็น downline มากขึ้น

6.1 ทำการทดลองธรรมดา (เปิดแค่เวอร์ชัน B ช่วงหนึ่งแล้วดูผล) ได้ไหม ข้อเสียคืออะไร? · 6.2 ควรใช้ metric อะไร? · 6.3 ควรแบ่งกลุ่มยังไง คุมอะไร? · 6.4 metric แจกแจงแบบไหน? · 6.5 กำหนด stopping criterion

<Solution label="แนวคำตอบ (ทำเอง ไม่ใช่เฉลยทางการ)">

**6.1** เปิดแค่ B แล้วเทียบกับช่วงก่อนหน้า = **ไม่มีกลุ่มควบคุมในช่วงเวลาเดียวกัน** ความต่างอาจมาจากปัจจัยที่เปลี่ยนตามเวลา เช่น seasonality, เทรนด์, ข่าว (ตำรวจกำลังตามมา!), แหล่งที่มาของผู้ชมที่เปลี่ยนไป ซึ่งเป็น confounder ทั้งหมด จึงสรุปเหตุและผลไม่ได้

**6.2** ปัจจัยที่เปลี่ยนคือทั้ง “อัตราการเป็น downline” และ “กำไรต่อคนที่ไม่เป็น downline” metric ที่ตรงเป้าหมายจริงคือ**กำไรเฉลี่ยต่อผู้ชมหนึ่งคน** แต่วัดได้จาก **downline conversion rate** = # downline / # ผู้ชม (ต่อคน ใน attribution period ที่ครอบคลุมเวลาที่คนตัดสินใจเป็น downline) แล้วแปลงเป็นกำไร

- เวอร์ชัน A: กำไรต่อผู้ชม $= 0.01(10{,}000) + 0.99(10) = 109.9$ บาท
- เวอร์ชัน B ที่อัตรา downline $q$: $10{,}000q + 5(1-q)$ จะคุ้มเมื่อ $\ge 109.9$ → $9{,}995q \ge 104.9$ → $q \ge 0.010495$

แปลว่า B ต้องเพิ่มอัตรา downline จาก 1% เป็นอย่างน้อย **1.0495%** (+0.05 เปอร์เซ็นต์พอยต์) ถึงจะคุ้มค่า bandwidth

**6.3** สุ่มตาม**ผู้ใช้ (account/cookie)** ให้คนเดิมเห็นเวอร์ชันเดิมเสมอ อาจแบ่ง 80/20 ถ้ากลัวเสียกำไร คุม confounder เช่น ช่องทางที่ผู้ชมมา (โฆษณาแต่ละแบบ), ช่วงเวลาที่เข้าชม ระวัง**ผู้ใช้มีปฏิสัมพันธ์กัน** (downline ชวนคนอื่นต่อ ข้อมูลรั่วข้ามกลุ่ม)

**6.4** ผู้ชมแต่ละคนเป็น downline หรือไม่ = **Bernoulli** → conversion rate เป็น normalized binomial ใช้ **two-proportion z-test** (one-sided: $H_A$: $q_B > q_A$ หรือดีกว่านั้นคือ $q_B > 0.010495$) ส่วนกำไรต่อคนเป็นการแจกแจงที่เบ้มาก (10,000 กับ 10 บาท) ไม่ normal

**6.5** ตั้ง MDE เท่ากับจุดคุ้มทุน 0.0005 (ความต่างที่เล็กกว่านี้ไม่คุ้ม) ใช้ $\sigma^2 = 0.01 \times 0.99$, one-sided α = 0.05, power 0.8, 50/50:

$$
n = 2 \times \frac{6.183 \times 0.0099}{0.0005^2} \approx 489{,}700 \text{ คนต่อกลุ่ม}
$$

ต้องใช้ผู้ชมเกือบล้านคน! เพราะ base rate ต่ำและ MDE เล็กมาก ถ้าเก็บไม่ไหวต้องยอมเพิ่ม MDE หรือลด power และต้องรันอย่างน้อยครบรอบสัปดาห์ ห้ามหยุดก่อนครบแม้จะเห็นผลระหว่างทาง

</Solution>
</Example>

<Example title="โจทย์ฝึก (final-exam-practice-problem): ลิงก์ในคอมเมนต์ช่วยไหม?">

Elon Mark ซื้อ Hambook แล้วเปลี่ยนชื่อเป็น “H” พร้อมเปลี่ยนอัลกอริทึม feed ทำให้โพสต์ของ Hamtaro แย่ลง 30% ทุก metric Koushi-kun ตั้งสมมติฐานว่า**ย้ายลิงก์ไปไว้ในคอมเมนต์**แทนในโพสต์จะช่วยได้ ข้อมูลโพสต์เก่า: โพสต์ 1–3 เป็นข่าวกีฬา โพสต์ 4–6 เป็นรีวิวร้านอาหาร โพสต์ 3 และ 6 คุณภาพต่ำ (นักเขียนจูเนียร์ใช้ ChadGPT) โพสต์ทั่วไปได้ยอดวิว 99% ในวันแรก และผู้ใช้ส่วนใหญ่เข้ามาช่วงพักเที่ยง

W1 metric อะไร? · W2 ทำการทดลองยังไง แบ่งกลุ่มยังไง คุมอะไร? · W3 ถ้ายอมรับการปรับปรุงอย่างน้อย 10% stopping criterion คืออะไร? · W4 ถ้าเปลี่ยนอัลกอริทึมทุกวันล่ะ?

<Solution label="แนวคำตอบ (ทำเอง ไม่ใช่เฉลยทางการ)">

**W1** เป้าหมายคือให้คนกดลิงก์ไปอ่านต่อ metric ที่ relevant คือ **จำนวนคลิก “Read more” / จำนวนคนที่เห็นโพสต์ (reach)** ต่อโพสต์ ส่วน reactions, likes, shares เป็น vanity metric ที่ไม่บอกว่าคนไปถึงเว็บ ข้อเสีย: comments อาจพุ่งขึ้นเองเพราะลิงก์อยู่ในคอมเมนต์ (frame the experiment fairly) จึงไม่ควรใช้ comments เป็น metric

**W2** เราสุ่มผู้ใช้ไม่ได้ (อัลกอริทึมเป็นของ H) จึงสุ่ม**ที่ระดับโพสต์**: แต่ละโพสต์ใหม่โยนเหรียญว่าจะวางลิงก์ในโพสต์ (A) หรือในคอมเมนต์ (B) คุม confounder: ประเภทโพสต์ (กีฬา/รีวิว ทำ test แยกหรือสุ่มภายในแต่ละประเภท), คุณภาพนักเขียน (ไม่ใช้โพสต์ ChadGPT หรือแบ่งให้เท่ากัน), เวลาโพสต์ (ช่วงเที่ยงเหมือนกัน), วันในสัปดาห์ เก็บ metric หลังโพสต์ครบ 1 วัน (ได้วิว 99% แล้ว)

**W3** MDE = 10% ของค่าเดิม ตั้ง α และ power (เช่น 0.05 และ 0.8) ประมาณ σ ของ metric ระหว่างโพสต์จากข้อมูลเก่า (หรือ A/A) แล้วใช้ $n = 2\left(\frac{(z_\alpha + z_\beta)\sigma}{\text{MDE}}\right)^2$ ได้จำนวน**โพสต์**ต่อกลุ่ม หยุดเมื่อได้ครบและครอบคลุมอย่างน้อยหนึ่งสัปดาห์ ห้ามแอบดูแล้วหยุดก่อน

**W4** ถ้าอัลกอริทึมเปลี่ยนทุกวัน ผลของวันหนึ่งใช้กับอีกวันไม่ได้ (ไม่ identically distributed) และการเทียบข้ามวันมี confounder คืออัลกอริทึม ทางหนึ่งคือ**โพสต์ทั้ง A และ B ในวันเดียวกัน** (จับคู่ตามวัน) แล้วใช้ paired test กับผลต่างรายวัน ความต่างของอัลกอริทึมแต่ละวันจะตัดกันไป

</Solution>

## สรุปสูตร + แบบฝึกหัด

### สรุปสูตรหน้าเดียว

| เรื่อง | สูตร / กฎ |
|---|---|
| 6 ขั้น | metric → split → test → stopping → run & monitor → analyze |
| Metric แบบ Bernoulli | $\hat p = \dfrac{\#\text{event}}{\#\text{unit}}$, $\sigma^2 = p(1-p)$ |
| Event-based | conversion ที่เกิดในช่วงนั้น / ผู้ใช้ในช่วงนั้น |
| Cohort-based | conversion ภายใน X วันของคนที่มาในช่วงนั้น / ผู้ใช้ในช่วงนั้น |
| Two-proportion z | $z = \dfrac{\hat p_B - \hat p_A}{\sqrt{\hat p(1-\hat p)(1/n_A + 1/n_B)}}$ |
| CI ของ conversion rate | $\hat p \pm z_{\alpha/2}\sqrt{\hat p(1-\hat p)/n}$ (บท LLN & CLT) |
| $z_\alpha$, $z_\beta$ | $z_\alpha = \Phi^{-1}(1-\alpha)$, $z_\beta = \Phi^{-1}(1-\beta)$, power 80% → $z_\beta = 0.842$ |
| ขนาดตัวอย่าง | $n = \dfrac{m+1}{m}\left(\dfrac{(z_\alpha + z_\beta)\sigma}{\text{MDE}}\right)^2$, กลุ่มทดลอง = mn |
| 50/50 | $n = 2\left(\dfrac{(z_\alpha + z_\beta)\sigma}{\text{MDE}}\right)^2$ ต่อกลุ่ม |
| Split rate m | 50/50 → 1, 33/67 → 2, 80/20 (ควบคุม/ทดลอง) → 0.25 |
| False positive จากหลาย test | คาดไว้ $m\alpha$ ครั้ง, $P(\ge 1) = 1 - (1-\alpha)^m$ |
| Bonferroni | $\alpha/m$ |
| Šidák | $1 - (1-\alpha)^{1/m}$ |

### แบบฝึกหัด

<Example title="ข้อ 1 (คำนวณขนาดตัวอย่าง)">

conversion เดิม 20% อยากตรวจให้เจอถ้าเพิ่มเป็น 22% ใช้ **two-sided** α = 0.05, power 80%, แบ่ง 50/50 ต้องใช้ตัวอย่างกลุ่มละกี่คน? ถ้ายอมให้ power เหลือ 50% ล่ะ?

<Solution label="เฉลย">

$\sigma^2 = p(1-p) = 0.2 \times 0.8 = 0.16$, MDE = 0.02, two-sided → $z_{\alpha/2} = 1.960$, $z_\beta = 0.842$

$$
n = 2 \times \frac{(z_{\alpha/2} + z_\beta)^2\,\sigma^2}{\text{MDE}^2} = 2 \times \frac{(1.960 + 0.842)^2 \times 0.16}{0.02^2} = 2 \times \frac{7.849 \times 0.16}{0.0004} = 6{,}279.1
$$

→ กลุ่มละ **6,280** คน

power 50% → $z_\beta = 0$: $n = 2 \times \dfrac{z_{\alpha/2}^2\,\sigma^2}{\text{MDE}^2} = 2 \times \dfrac{1.960^2 \times 0.16}{0.0004} = 3{,}073.3$ → กลุ่มละ **3,074** คน (น้อยลงครึ่งหนึ่ง แต่ถ้าผลจริงเท่ากับ MDE พอดี จะเจอแค่ครึ่งเดียวของการทดลอง)

</Solution>

### HW12 ข้อ 3: Event-based vs Cohort-based

<Example title="HW12 ข้อ 3">

ใช้ attribution period 7 วัน และ conversion rate = purchases / unique users

| date | user | event |
|---|---|---|
| 2020-11-01 | A | visit |
| 2020-11-01 | A | purchase |
| 2020-11-05 | B | visit |
| 2020-11-13 | B | visit |
| 2020-11-30 | C | visit |
| 2020-12-05 | C | purchase |

1. Event-based conversion rate ของเดือน 2020-11 คือเท่าไร
2. Cohort-based conversion rate ของเดือน 2020-11 คือเท่าไร

<Solution>

ผู้ใช้ที่เข้ามาในเดือนพฤศจิกายน: A, B, C รวม **3 คน** (B เข้า 2 ครั้งแต่นับเป็นคนเดียว)

**1. Event-based** นับเฉพาะ purchase ที่**เกิดในเดือนพฤศจิกายน**

$$
\text{CR}_{\text{event}} = \frac{\text{purchase ที่เกิดใน 11}}{\text{unique users ใน 11}} = \frac{1 \text{ (A)}}{3} \approx 33.3\%
$$

**2. Cohort-based** ติดตามคนที่เข้ามาในพฤศจิกายนต่อไปอีก 7 วัน แม้จะข้ามเดือน

- A: เข้า 11-01 ซื้อวันเดียวกัน → นับ
- B: ไม่ซื้อ
- C: เข้า 11-30 ซื้อ 12-05 ห่างกัน 5 วัน ≤ 7 วัน → นับ

$$
\text{CR}_{\text{cohort}} = \frac{\text{คนใน cohort 11 ที่ซื้อภายใน 7 วัน}}{\text{unique users ใน cohort 11}} = \frac{2 \text{ (A, C)}}{3} \approx 66.7\%
$$

ต่างกันตรง C ที่มาปลายเดือนแล้วไปซื้อต้นเดือนถัดไป event-based จะไปนับการซื้อนี้ให้เดือนธันวาคมแทน

</Solution>
</Example>

### HW12 ข้อ 9: ขนาดตัวอย่างเมื่อแบ่ง 80/20

<Example title="HW12 ข้อ 9">

Hamster Inc. ทดสอบซองสีแดง (กลุ่มควบคุม conversion เดิม 11%) กับซองสีทอง ตั้ง MDE = 1% แบ่ง control/test เป็น 80/20 ใช้ significance level 15% และ power 80% ต้องให้ผู้ใช้เห็นซองแต่ละสีกี่คน?

<Solution>

**ขั้นที่ 1: สูตรจากสไลด์** (กลุ่มควบคุม n คน กลุ่มทดลอง mn คน)

$$
n = \frac{m+1}{m}\left(\frac{(z_\alpha + z_\beta)\,\sigma}{\text{MDE}}\right)^2
$$

**ขั้นที่ 2: เตรียมค่า**

- $\sigma^2 = p(1-p) = 0.11 \times 0.89 = 0.0979$
- $\text{MDE} = 0.01$ (จาก 11% เป็น 12%)
- $z_\alpha = \Phi^{-1}(1 - \alpha) = \Phi^{-1}(0.85) = 1.036$
- $z_\beta = \Phi^{-1}(1 - \beta) = \Phi^{-1}(0.80) = 0.842$
- $m = \dfrac{\text{test}}{\text{control}} = \dfrac{20}{80} = 0.25$

**ขั้นที่ 3: แทนค่า**

$$
n = \frac{0.25 + 1}{0.25} \times \frac{(1.036 + 0.842)^2 \times 0.0979}{0.01^2} = 5 \times \frac{3.527 \times 0.0979}{0.0001} = 5 \times 3453.0 = 17{,}265.1
$$

**ขั้นที่ 4: ปัดขึ้นเสมอ**

- กลุ่มควบคุม (แดง): **17,266** คน
- กลุ่มทดลอง (ทอง): $m \times n = 0.25 \times 17{,}265.1 = 4{,}316.3$ → **4,317** คน
- รวม **21,583** คน

</Solution>
</Example>

<Warn title="z_α ของสูตรนี้เป็นแบบหางเดียว">

สูตรในสไลด์ใช้ $z_\alpha = \Phi^{-1}(1-\alpha)$ (one-sided) ถ้าข้อสอบบอกว่าทดสอบสองทาง ต้องใช้ $z_{\alpha/2} = \Phi^{-1}(0.925) = 1.440$ แทน ข้อนี้จะได้กลุ่มควบคุม 25,472 คน และกลุ่มทดลอง 6,368 คน (มากขึ้นราว 48%) และระวังอย่าสลับ m: m คือ “กลุ่มทดลอง ÷ กลุ่มควบคุม” แบ่ง 80/20 จึงได้ 0.25 ไม่ใช่ 4

</Warn>

### HW12 ข้อ 10: ซองไหนชนะ (two-proportion z-test + CI)

<Example title="HW12 ข้อ 10">

ผลการทดลองของ Hamster Inc.

| campaign | clicks | conv_cnt | conv_per |
|---|---|---|---|
| Red | 59,504 | 5,901 | 0.099170 |
| Gold | 58,944 | 6,012 | 0.101995 |

1. ที่ significance level 7% ควรเลือกแบบไหนไปใช้กับ traffic 100%? ทำ hypothesis test
2. หา confidence interval ที่ significance 7% (คือ 93% CI) ของ conversion rate ของ Red และ Gold

<Solution>

**1. ตั้งสมมติฐาน** จะเปลี่ยนไปใช้ Gold ก็ต่อเมื่อ Gold ดีกว่า จึงเป็น one-sided

$$
H_0: p_G = p_R, \qquad H_A: p_G \gt p_R
$$

**สูตร two-proportion z-test**

$$
\hat p = \frac{x_R + x_G}{n_R + n_G}, \qquad z = \frac{\hat p_G - \hat p_R}{\sqrt{\hat p(1-\hat p)\left(\frac{1}{n_R} + \frac{1}{n_G}\right)}}
$$

**แทนค่า**

- $\hat p_R = \dfrac{5901}{59504} = 0.09917$, $\hat p_G = \dfrac{6012}{58944} = 0.10200$
- $\hat p = \dfrac{5901 + 6012}{59504 + 58944} = \dfrac{11913}{118448} = 0.10058$
- $SE = \sqrt{0.10058 \times 0.89942 \times \left(\frac{1}{59504} + \frac{1}{58944}\right)} = 0.001748$

$$
z = \frac{0.10200 - 0.09917}{0.001748} = 1.616
$$

**ตัดสินใจ:** critical value $z_{0.07} = \Phi^{-1}(0.93) = 1.476$ และ $1.616 \gt 1.476$ (p-value $= P(Z \gt 1.616) = 0.053 \lt 0.07$) จึง**ปฏิเสธ $H_0$ เลือก Gold**

**2. CI ของแต่ละกลุ่ม** สองทาง ใช้ $z_{\alpha/2} = z_{0.035} = \Phi^{-1}(0.965) = 1.812$

$$
\hat p \pm z_{\alpha/2}\sqrt{\frac{\hat p(1-\hat p)}{n}}
$$

| | $SE = \sqrt{\hat p(1-\hat p)/n}$ | margin $= 1.812 \times SE$ | 93% CI |
|---|---|---|---|
| Red | 0.001225 | 0.00222 | [0.0969, 0.1014] |
| Gold | 0.001247 | 0.00226 | [0.0997, 0.1043] |

</Solution>
</Example>

<Warn title="2 จุดที่คนพลาดในข้อนี้">

1. **one- หรือ two-sided เปลี่ยนคำตอบ:** ถ้าใช้ two-sided จะต้องใช้ $z_{0.035} = 1.812$ และ $1.616 \lt 1.812$ (p = 0.106) จะปฏิเสธไม่ได้ ต้องเลือกให้ชัดและให้เหตุผลก่อนดูข้อมูล
2. **CI ซ้อนกันไม่ได้แปลว่าไม่ significant:** CI ของ Red กับ Gold ซ้อนกันอยู่ช่วง [0.0997, 0.1014] แต่ test ยังให้ significant เพราะ test ดูที่**ผลต่าง**ซึ่งมี SE เล็กกว่าการเอาสองช่วงมาเทียบกันตรงๆ

### HW12 ข้อ 11: จริงหรือเท็จเกี่ยวกับ frequentist A/B test

<Example title="HW12 ข้อ 11">

11.1 ไม่ได้บอกขนาดความต่างระหว่างกลุ่มควบคุมกับกลุ่มทดลอง · 11.2 เราไม่มีทางรู้ว่าจะหยุดการทดลองเมื่อไร · 11.3 เราพิสูจน์ไม่ได้ว่า $H_0$ เป็นจริง · 11.4 จะรันกี่การทดลองก็ได้โดยใช้ significance level เดิม · 11.5 ถ้าตัวอย่างในแต่ละกลุ่มมากเกินไป ความน่าเชื่อถือของการทดสอบอาจเสียได้ · 11.6 ถ้าตั้งการทดลองตาม MDE และ α แล้ว statistical significance เป็นปัจจัยเดียวที่ใช้ตัดสินว่ากลุ่มไหนดีกว่า · 11.7 ทดสอบได้แค่ความต่างของสองสัดส่วน · 11.8 ตัวอย่างยิ่งมากยิ่งดีเสมอ

<Solution label="เฉลย">

- **11.1 จริง:** p-value ไม่บอกขนาดหรือความสำคัญของผล (misuse ข้อ 4) ต้องดู effect size หรือ CI เพิ่ม

- **11.4 เท็จ:** ต้องแก้ multiple testing (Bonferroni, Šidák, B-H)
